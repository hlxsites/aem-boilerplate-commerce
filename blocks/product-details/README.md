# Product Details Block

## Overview

The Product Details block composes product detail, cart, wishlist, and ratings/reviews drop-ins. It displays product information and options, lets shoppers add or update a cart item, and optionally displays a read-only review section below the purchase area.

## Integration

### Block Configuration

The block uses the PDP initializer to resolve the product and load its data. Product identification follows these rules:

- On storefront pages, `sku` page metadata takes precedence over the SKU in `/products/{urlKey}/{sku}`.
- In authoring modes (`dapreview` present or `quick-edit=on`), `sku` metadata takes precedence over the authored `defaultsku` block configuration.

| Configuration Key | Type | Default | Description | Required | Side Effects |
| --- | --- | --- | --- | --- | --- |
| `defaultsku` | string | None | Fallback SKU for authoring when `sku` page metadata is absent. Ignored for normal storefront product identification. | No | Selects the product previewed in the editor. |

Review enablement and page size are not authored block configuration options.

### URL Parameters

| Parameter | Format | Behavior |
| --- | --- | --- |
| `itemUid` | Cart item UID | Selects update mode only when the UID matches an item in the current `cart/data` payload. Otherwise, the block stays in add mode. |
| `optionsUIDs` | Comma-separated option UIDs | Passed to PDP initialization to preselect product options. Wishlist updates use the current selection; an explicitly empty `optionsUIDs=` clears option UIDs from the wishlist context. |
| `dapreview` | Presence of the parameter | Enables authoring SKU resolution through page metadata or `defaultsku`. |
| `quick-edit` | `on` | Enables the same authoring SKU resolution. Other values do not enable this mode. |

After a successful cart-item update, the block redirects to the localized cart page with the matching `itemUid` query parameter.

### Ratings and Reviews

The block lazily loads [reviews.js](./reviews.js) after rendering purchase controls. The helper adds a full-width review region below the product layout, separate from the PDP `ProductRating` beneath the product name.

| Setting | Source | Behavior |
| --- | --- | --- |
| `product_reviews_enabled` | Backend `storeConfig`, normalized to `isProductReviewsEnabled` | Must resolve to `true` to mount the review region or request aggregate/list data. Missing, disabled, or failed configuration keeps the region hidden. |
| `allow_guests_to_write_product_reviews` | Backend `storeConfig` | Does not gate read-only display. Guests can read reviews even when guest writing is disabled. |
| Product SKU | Initial `pdp/data` payload | Used for both aggregate and list requests. Later variant or quantity changes do not change review ownership or trigger refetches. |
| `pageSize` / `currentPage` | Fixed in the helper | Requests the first 20 reviews on page 1. There are no block or URL overrides. |
| `scope` | Generated by the helper | A private `pdp-reviews-<UUID>` scope shared by the Rating and Review containers and their API requests. |

The [ratings/reviews initializer](../../scripts/initializers/ratings-reviews.js)
inherits `CS_FETCH_GRAPHQL`, including its configured endpoint and headers.
The Router must support `STORE_CONFIG_QUERY`, `PRODUCT_RATING_QUERY`, and
`REVIEWS_QUERY`. Do not hard-code a tenant endpoint into the block.

The approved review count comes from the aggregate response, not from the number
of displayed review items. The current integration does not include a
distribution graph, Troop Leader badge, pagination controls, sorting, review
submission, or helpfulness voting.

The Review container supplies its own loading skeleton and localized status
message. The average Rating container exposes loading state but no default visual
placeholder, so this block fills its `Loading` slot with the shared drop-in
Skeleton components. Both containers expose `aria-busy`; the decorative
skeletons are hidden from assistive technology and do not block purchase controls.

### Localization

PDP labels are loaded through `placeholders/pdp.json`. Cart action labels use the
shared `Global` dictionary, including `AddProductToCart`, `UpdateProductInCart`,
`AddingToCart`, and `UpdatingInCart`.

Review labels can be overridden through `placeholders/ratings-reviews.json`,
using dotted keys. The drop-in supplies its default review dictionary.

| Placeholder | Purpose |
| --- | --- |
| `Rating.error` | Aggregate request failure. Defaults to `Unable to load rating.` |
| `Rating.unavailable` | Aggregate request succeeded without a matching product. Defaults to `Rating is unavailable.` |
| `Review.title` | Review heading when the approved total is unavailable. |
| `Review.oneReview`, `Review.reviews` | Singular/plural review headings; the plural message supports `{{count}}`. |
| `Review.loading`, `Review.empty`, `Review.unavailable`, `Review.error` | Review-list status messages. |
| `Review.retry` | Label for the review-list retry button. |
| `Review.author`, `Review.unrated`, `Review.dateLocale` | Review author text (`{{nickname}}`), unrated label, and date-formatting locale. |

### Events

#### Event Listeners

These listeners belong to [product-details.js](./product-details.js).

| Event | Payload used | Effect |
| --- | --- | --- |
| `pdp/data` | Product data, including `sku` and `inStock` | Updates the current product, purchase-button stock state, and action label. Replays the last event on subscription. |
| `pdp/valid` | Boolean | Updates purchase-button availability using configuration validity and current stock state. Replays the last event. |
| `pdp/values` | Reads current selection through `getProductConfigurationValues()` | Updates the WishlistToggle product and option UIDs. Replays the last event. |
| `wishlist/alert` | `{ action, item }` | Renders a wishlist alert, scrolls it into view, and clears it after five seconds. |
| `cart/data` | Cart data with `items[].uid` | Checks whether `itemUid` exists in the cart and updates add/update mode and button text. Replays the last event. |
| `commerce/customer-context` | Payload is not read | Refetches the current product with the selected option UIDs so pricing reflects the new customer context. |

#### Event Emitters

- `pdp/data`: emitted with refreshed product data after a `commerce/customer-context` refetch succeeds.

Cart and wishlist operations also produce their respective drop-in events. The block delegates those operations to the drop-in APIs rather than emitting replacement result events itself.

#### Scoped Ratings/Reviews Events

The ratings/reviews APIs publish these events; their containers subscribe using the helper's private scope. They are not direct unscoped listeners in the block.

| Event family | Payload | Purpose |
| --- | --- | --- |
| `rating/request` | `{ sku }` | Identifies the requested aggregate. |
| `reviews/request` | `{ sku, pageSize, currentPage }` | Identifies the requested review page. |
| `rating/loading`, `reviews/loading` | Boolean | Controls request/loading state. |
| `rating/result`, `reviews/result` | `{ request, result }` | Publishes the matching request and normalized result, which may be `null` when unavailable. |
| `rating/error`, `reviews/error` | Error message string or `null` to clear | Controls each container's failure state independently. |

When customizing [reviews.js](./reviews.js), retain the same scope on related container props and API options. Do not manually emit result events or share the scope with unrelated product displays.

## Behavior Patterns

### Page Context Detection

- **Add mode**: the current cart does not contain the requested `itemUid`. Valid selections are passed to `addProductsToCart`.
- **Update mode**: the current cart contains the requested `itemUid`. Selections and the UID are passed to `updateProductsFromCart`, then the shopper returns to the cart.
- **Product configuration**: PDP containers manage options and quantity; validity and stock events update purchase availability.
- **Reviews disabled or product missing**: the lower review region is not mounted. Existing PDP and purchase rendering remain separate.

### User Interaction Flows

1. **Product display**: renders the gallery, header rating, price, short description, options, quantity, full description, and attributes.
2. **Cart action**: adds the current configuration or updates a matching cart item. The button shows progress and a live status announces the operation.
3. **Wishlist action**: toggles wishlist membership using the current product selection and displays the resulting alert.
4. **Review display**: initializes review configuration, mounts average Rating and Review containers, and requests their data in parallel.
5. **Review retry**: the Review container's retry button requests the same SKU, page size, and page in the same scope.
6. **SEO**: prerendering is responsible for metadata and JSON-LD. The block does not write SEO metadata at runtime.

### Error Handling

- **Cart requests**: show a dismissible alert with the returned error message and restore the purchase-button label after the operation.
- **Review configuration**: failure is logged and leaves review display disabled.
- **Aggregate requests**: show the localized aggregate error or unavailable message without hiding a successful review list.
- **Review-list requests**: show the drop-in's localized status and retry control without hiding a successful aggregate.
- **Review initialization**: failures are logged with the `[Product Reviews]` prefix and do not reject the main block decoration.
