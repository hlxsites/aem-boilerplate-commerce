# Commerce B2B Requisition List Public Share Block

## Overview

The Commerce B2B Requisition List Public Share block handles incoming **public** requisition list share links — links that can be opened by guests or by signed-in shoppers outside the owning company. It uses the `SharedRequisitionList` container from `@dropins/storefront-requisition-list` (in `isPublic` mode) to render a read-only preview of the shared list.

Unlike the private [`commerce-b2b-requisition-list-sharing`](../commerce-b2b-requisition-list-sharing/README.md) block, this block never gates on authentication and never imports the list into an account. Recipients can select items from the preview and add them to their own cart (guest cart created on demand if none exists).

## Integration

### URL Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `requisition_id` | `string` | One of `requisition_id`/`token` is required | Public share token generated by the list owner (the in-app copy-link field uses this param). If missing, the block redirects to the storefront home page. |
| `token` | `string` | One of `requisition_id`/`token` is required | Same public share token, under the param name the backend public share email uses. Checked when `requisition_id` is absent. |

### Block Configuration

| Configuration Key | Type | Default | Description | Required | Side Effects |
|-------------------|------|---------|-------------|----------|--------------|
| – | – | – | This block has no authorable configuration. | – | – |

### Authoring

Shared links only work if a page exists at the path configured in the `requisition_list_public_share_storefront_path` store configuration. The default is `/customer/requisition-list-public-share`. If no page is authored there, every public share link (email and copy-link) returns a 404.

1. Create a page at that path in DA.
2. Add a one-cell block table with the heading `Commerce B2B Requisition List Public Share`.
3. Preview and publish the page.

This page must be different from the private share page (`requisition_list_share_storefront_path`), which uses the `commerce-b2b-requisition-list-sharing` block. The owner's share modal (in `commerce-b2b-requisition-list-view`) builds the link from the same config value. If you change the path in Commerce Admin, move the authored page to the new path and set `CYPRESS_requisitionListPublicSharePath` for the E2E tests.

## Behavior Patterns

### User Interaction Flows

1. **No token** — Neither `?requisition_id` nor `?token` is present → the block replaces the current history entry with the storefront home page (`location.replace`), so the browser Back button doesn't return to the broken link.
2. **Guest or signed-in recipient** — Token present → `SharedRequisitionList` dropin loads a read-only preview (sender name, list name, items, pagination) regardless of authentication state or company membership. Product name/image link to the PDP via `routeProduct(urlKey, sku)`, built from the item's own `urlKey`/`sku`.
3. **Add to cart** — Recipient selects one or more items and adds them to their own cart:
   - A guest cart is created on demand if the recipient has none yet; an authenticated recipient's existing customer cart is reused.
   - A signed-in recipient never falls back to a guest cart: if their customer cart can't be loaded, the add-to-cart fails with an error instead of putting items in a cart they can't see.
   - After the mutation, `onCartUpdated` calls `refreshCart()` so the header cart badge reflects the new items.
4. **Import** — Not available. Public recipients can only add items to cart, never import the list into an account.

### Error Handling

- **Missing token**: Redirected to the home page (`location.replace`) before any dropin code runs.
- **Invalid / expired token**: `SharedRequisitionList` dropin displays an inline error alert.
- **Cart resolution errors**: If the customer cart can't be loaded (signed-in) or a guest cart can't be created (guest), the error is logged to the console and `getCartId` returns `null`. The dropin then shows its localized cart error alert and adds nothing to any cart.
- **Add-to-cart errors**: GraphQL `userErrors` (out of stock, invalid quantity, and so on) are displayed by the dropin (`cart_error` status).
- **Cart refresh errors**: If `refreshCart()` fails after a successful add-to-cart, the error is logged and ignored. The shopper still sees the success message, and the header badge updates on the next cart refresh.
- **Network / API errors**: Handled and displayed by the dropin.
